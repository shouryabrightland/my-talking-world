# Tom & Friends — Codebase Documentation

A React 19 + Vite single-page app that simulates a living group chat between six
cartoon characters (**Tom, Angela, Ben, Ginger, Hank, Becca**) and a human user,
grounded in Lucknow, India. Dialogue is generated by **Groq** (fast SSE streaming,
Hinglish banter), while the 24-hour schedule, long-term memory extraction and news
distillation are planned by **Gemini/Gemma** via Google AI Studio. Built for the
CBSE Hackathon 2026 showcase — strictly G-rated and child-safe.

---

## 1. Architecture at a Glance

```
React UI (src/components + src/contexts)
        │  useChat()
        ▼
ConversationManager  ──── turn orchestration, prompt assembly, director twists
   │        │         \
   │        │          └── GroqClient ── GroqModelPool ── SSE streaming dialogue
   │        ├── TimelineProcessor ── ChatMemberScheduler(s) ── typing/reading/message pacing
   │        ├── SituationEngine (Gemma) ── memory extraction + news distillation
   │        └── ProtocolCodec ── XML <record>/<msg>/<delay> parsing
   ▼
World  ── simulation clock, active schedule block, environment snapshot, XML context
   └── WorldSetter (Gemini) ── hybrid 24h planner: templates + delta gaps + demand engine
        └── UnifiedMemory ── single ≤80-char tag-indexed memory store (+ NeedleRouter)
Chat   ── message array, participants, IndexedDB persistence (MessageStore → Storage)
```

Cross-cutting: `EventManager` (insulated pub/sub), `Logger` + `PromptLogger`
(ring buffers feeding DevTools), `CircuitBreaker`/`RateLimiter` (API protection),
`environment.js` (live weather, festivals, news).

## 2. `src/classes/` — Core Simulation Domain

### `ConversationManager.js`
Central dialogue flow and turn orchestrator — the heart of the app.
- Registers prompt blocks (`registerPrompt()`) on a `PromptBuilder`: child-safety
  mandate, language mandate, location mandate, current scene (`## Current Scene:
  <title> (<timeRange>)` + the planner's `denseParagraph`), active memories,
  recent dialogue, and any active director twist (`pre_plot`/`mid_plot`/`post_plot`).
- Drives the Groq streaming loop, parses `<msg>`, `<delay sec="…"/>` and
  `<next time="HH:MM"/>` from the stream, and schedules the next turn.
- **Message splitting**: `splitMessageText()` guarantees no bubble exceeds 140 chars;
  `handleBanterMessage()` fans a long line into several `Message` objects with
  1000–1500 ms inter-message delays so bubbles pop in sequentially.
- **Director Twist Engine**: `injectDirectorPlot()` with a 30 s cooldown
  (`directorCooldownUntil`), a max of 2 active twists (`activeDirectives`),
  conflict cancellation parsed from Gemma's `<twist_analysis>` XML, and an
  end-of-twist lock (`endLockUntilTurn`). Emits `DIRECTOR_TWIST_CHANGE` for the
  footer rail.
- Triggers `situationEngine.ingestNews()` on the hourly environment refresh.

### `World.js`
Pure state container for the simulation environment.
- Holds simulation time, the active `ScheduleRecord`, and the `EnvironmentSnapshot`.
- 30-second heartbeat clock that detects hour/day rollovers and re-resolves the day.
- Registers AI members and the human user; renders the structured `<world>` XML
  context (location, weather, occasion, scene, goals) for prompts.
- 10 %/90 % temporal phasing of schedule segments (opening/core/transition).
- Owns `syncEnvironment`/`syncPlannerScenes` calls that push real-world data and
  future scenes into `UnifiedMemory`.

### `WorldSetter.js`
Hybrid 24-hour planner powered by Gemini (deep-thinking budgets, Google Search tool).
- **Two storage keys**: `world:schedule_templates` (recurring blocks: `forever`,
  `weekdays`, `weekends`, specific dates) and `world:schedule_today` (today's
  resolved contiguous timeline). Legacy monolithic horizon key is migrated on boot.
- `resolveTodaySchedule(now)` — priority ladder **specific date > day group >
  daily routine**, non-destructive overrides, detection of empty gaps (0.0–24.0 h),
  Gemini generation of **delta-only** blocks (`type:"once"`, `source:"delta"`), and
  deterministic backfill so the day is always contiguous.
- `planHorizon()` — full-day planning prompt (injects the child-safety + age mandates).
- Director Demand engine — inserts a user-requested activity, preserves surrounding
  blocks, and returns a `<narrative_report>`.
- `reorderBlocks(index, direction)` — free reordering with direct persistence and
  **no** AI re-stabilization; `regenerateUpcomingDeltas()` re-runs gap filling when a
  cast bio changes (`ChatMemberEvents.ABOUT`).
- Stabilizer pass (`restabilizeAndSave`) reconnects user-edited blocks into one story.

### `SituationEngine.js`
Tier-2 memory & news engine (Gemma via Google AI Studio). **Memory/news only** — it
never rewrites the macro scene paragraph (that's the planner's `denseParagraph`).
- **Triggers**: forced pass at boot/session reset; immediate pass when
  `unreadMessagesCount >= 6` (volume trigger, which also resets the timer); periodic
  1-minute pass only while `unreadMessagesCount > 0`. Single-flight via `isProcessing`.
- Extracts new ≤80-char memories from dialogue and prunes stale ones through
  `<deletions><delete index="…"/></deletions>`.
- `ingestNews(headlines)` condenses top environment headlines into 3–5 factual
  ≤80-char records tagged `["%world%","news",…]` with a 1 h TTL.

### `Chat.js`
Chat room orchestrator.
- In-memory message array plus message/protocol-ID lookup maps.
- Participant registration and lifecycle events (`ChatEvents`: member add/remove).
- Syncs messages to IndexedDB via `MessageStore`; trims history above 1000 messages;
  repairs reply reference links by protocol ID.

### `ChatMember.js`
A single participant (AI character or the human user).
- Stores bio, birthday and computed age; exposes transient visual state
  (`isTyping`, `isReading`, `isThinking`, `isActive`, `emotion`) as plain in-memory
  fields — **nothing visual is persisted** (legacy keyed memory was removed).
- `setTransientState(key, value, durationMs)` sets flags and emits events without
  touching IndexedDB.
- Calculates human-like typing/reading pacing delays; owns a `ChatMemberScheduler`
  and connects/disconnects from the `Chat` room.

### `Message.js`
Data structure for one conversational exchange: body text, sender reference,
emotion metadata, parent/child reply links via protocol IDs, soft-delete and
sent-state flags, JSON (de)serialization for IndexedDB, and LLM prompt-ready
string rendering.

### `Reaction.js`
Static metadata registry mapping emotion names (Default, Happy, …) to sprite-sheet
coordinates and emoji codes, with case-insensitive lookup and a strict default.

### `TimelineProcessor.js`
Pacing brain for the chat feed.
- Computes human-like typing and reading delays, resolves reply hierarchies, and
  derives deterministic request pacing.
- `process(messages, interMessageDelay = 0)` / `add(message, interMessageDelay)` /
  `#processMessage(message, interMessageDelay)` — `senderTime` is offset by
  `Math.max(0, interMessageDelay)` so split bubbles arrive sequentially with
  realistic typing animations and pauses.

### `GroqClient.js`
Unified Groq REST + SSE streaming client.
- Zero hardcoded model chains — models come from `GroqModelPool` (dynamic discovery).
- Streams chat completions with real-time token emission; also non-streaming fallback.
- `applyGroqThinking(body)` sets `reasoning_effort: "low"` and tops up `max_tokens`
  by `GROQ_THINKING_BUDGET_TOKENS` (512) on reasoning models only.
- Parses `usage.completion_tokens_details.reasoning_tokens` and records it as
  `tokensThinking` on every `PromptLogger` entry (both stream and fallback paths).
- Rate limiting driven by real `x-ratelimit-*` headers, HTTP 429/503 handling with
  exact server-timed cooldowns, and circuit-breaker protection.

### `GeminiClient.js`
Lightweight stateless Gemini REST client with dynamic model-capability adaptation.
Exports `GOOGLE_SEARCH_TOOL`, `DEEP_THINKING_BUDGET`, `STABILIZER_THINKING_BUDGET`.
Emits streamed text events, wraps calls in a `CircuitBreaker`, strips `<thought>`
spans via `ProtocolCodec`, and logs every call to `PromptLogger`.

### `ProtocolCodec.js`
Hardened XML tag protocol codec for streaming/reasoning models.
- Strips markdown fences (```xml), parses structured `<record>` tags safely, and
  enforces a 32 768-char max buffer (corrupt leading text is discarded).
- Splits `<think>…}` reasoning chains from clean payload text; residual
  `<thought>` spans are stripped from message bodies so they never reach a bubble.

### `PromptBuilder.js`
Assembles and compiles structured, context-heavy prompt payloads for Groq's
OpenAI-compatible API. Subsystems register decoupled prompt blocks (sync or async);
each block executes inside a safe error boundary so one broken block can never
kill a turn. Produces `{ messages: [...] }`.

## 3. `src/classes/lib/` — Infrastructure Utilities

| File | Role |
|---|---|
| `UnifiedMemory.js` | The single tag-indexed memory store replacing all legacy keyed memory. Enforces `MAX_RECORD_CHARACTERS = 80` via `clampRecord()` on `add()` **and** on legacy entries loaded from IndexedDB. `searchDeterministic(keywords, targetTags)` scores: cast-member tag **+5**, content keyword **+3**, `%world%` news **+2** (only when the query contains news/weather/world keywords), and never returns more than one `%world%` entry in the top 2 so personal memories always win. `syncEnvironment()` seeds the celebration string, the **next 10 calendar events** (`In <n>d: <name> (<date>)`, 24 h TTL) and raw headlines; `syncPlannerScenes()` mirrors future planner blocks for recall. |
| `NeedleRouter.js` | Synchronous deterministic Tier-3 query router (microseconds, no workers/Wasm). Word-boundary regexes for cast names (`\btom\b`, …) so "thank you" never routes to Hank; English + Hinglish stopword filtering; returns `{ keywords: string[], member: string }` (max 3 keywords, `member` defaults to `"any"`). |
| `ChatMemberScheduler.js` | Per-member chronological queue of `typing:start/end`, `reading:start/end` and `message` events, persisted to IndexedDB. **Reload catch-up**: `init()` flushes every past-due event before releasing `readyPromise`; past-due messages always deliver regardless of age, while visual cues older than 4 s are skipped so a reload never replays stale typing animations. Sequential mutex-locked persistence queue. |
| `Storage.js` | Promise-based IndexedDB wrapper with a localStorage-like API (`getItem`/`setItem`/`removeItem`/`clear`). Handles versioning/upgrades, multi-tab `onversionchange`, aborted-transaction recovery, corruption auto-rebuild, and retry-on-transient-failure. |
| `MessageStore.js` | Persistent message layer over `Storage`: serial write chain, 1000-message cap, corrupt-record recovery, chronological restore. |
| `Logger.js` | Structured, severity-filtered logging with hierarchical child loggers (`World/Members/Tom`). Four independent in-memory ring buffers (errors 100, warns 150, infos 250, debugs 350) so chatty debug output can never evict critical entries; subscription hooks stream to DevTools inside try/catch boundaries. |
| `PromptLogger.js` | In-memory ring buffer of the last 5 LLM executions per type (`dialogue`, `scheduler`, `demand`, `stabilizer`, `situation`). `PromptLogEntry` records id, model, messages, latency, status, error details, extracted thinking, and `tokensThinking: number|null` (reasoning tokens inside the 512-token budget). Live subscription hooks feed the DevTools Prompts tab. |
| `CircuitBreaker.js` | Three-state (`closed` / `open` / `half_open`) failure barrier protecting API calls from cascading failures, with timed recovery probes. |
| `RateLimiter.js` | Rolling-window limiter enforcing max-per-minute, minimum spacing, and max concurrency, mutex-serialized for async safety. |
| `GroqModelPool.js` | 100 % dynamic Groq model discovery: queries `GET /models` with the user's key, filters out guard/whisper/tts/embedding/vision models and anything below 12 B parameters, then tiers the survivors (≥70 B flagship, 20–70 B mid, 12–20 B/MoE). Self-healing cooldowns track real server reset headers. |
| `GeminiModelResolver.js` (`GeminiModelPool`) | Dynamic, self-healing Gemini model pool for the planner: discovers models, classifies flash/flash-lite variants, ranks by tier and version, honours a user blocklist. |
| `MemoryExpiryParser.js` | Parses memory TTL strings — `15m`, `2h`, `7d`, `2w`, `forever`/`-1` — into a Date or "never expires". Extracted from ConversationManager for reuse and testing. |
| `XmlEncoder.js` | Shared `encode`/`decode` XML entity utilities (escapes `& < > " '`), de-duplicating logic that previously lived in ConversationManager, World and WorldSetter. |
| `UserInterruptHandler.js` | Human interruption logic: cancels AI queues on submit, bypasses the debounce for explicit Send/Enter while the user is idle, and defers turns until the typing cadence settles (with a 3 s safety net) when the user keeps typing. |

## 12. Quality Gates

```bash
npm run typecheck   # tsc --noEmit        → 0 errors
npm run lint        # eslint .            → clean
npm test            # vitest run          → 39 files, 477/477 passing
npm run build       # vite build          → PresentationView code-split into its own async chunk
npm run test:ci     # the full pipeline (lint → typecheck → coverage → e2e → build)
```

Runtime constraints worth knowing: memory records are hard-capped at **80
characters**; chat bubbles are hard-capped at **70 characters** (with programmatic
splitting as fallback); Groq thinking runs on a **512-token** budget at
`reasoning_effort: "low"`; the Director engine enforces a **30-second** cooldown with
a **max of 5** concurrent twists; persistent chat history is capped at **1000**
messages; and environment data is cached for **20 minutes**.
